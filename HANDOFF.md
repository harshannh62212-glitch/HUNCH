**Data flows worth remembering:**

1. **Human drives in browser** (`viewer.html`, WASD) → optional **Record Demonstration** → `dataset_latest.json` → **PyTorch trainer** → `rover_pilot.onnx` → loaded back in the browser via **ONNX Runtime WebAssembly** (~60 FPS).
2. **Simulator telemetry** can POST to `serve.py` **`/api/log`** → appended to `rover_actions.log`.
3. **Macro dodge decisions** for surface nav are defined in **`payload.json`** (Ollama-style chat template for `qwen2.5-coder:7b`); the LLASO viewer can talk to a local **Ollama** instance for strategic planning when available.
4. **Manifest** is regenerated by Python; the **viewer** reads `lunar_logistics_manifest.json` for timeline scrubbing and item inspection.

## 5. Subsystem reference

### 5.1 AEGIS-V1 — Root mission dashboard (`/`)

**Purpose:** Public-facing **LLASO Project 2** engineering site: interactive 3D CAD inspection of the Polymaker Black PETG Rover & HQST 100W Solar Garage Docking Bay, route animation, and payload math.

**Key files:**

- `index.html` — layout, Tailwind (CDN), Three.js, sections (overview, CAD inspection, route, calculator, team).
- `app.js` — all client logic (single `DOMContentLoaded` bundle).
- `styles.css` — supplemental styling.
- `vercel.json` — project name `aegisv1`, `cleanUrls: true`.

**What `app.js` does (three blocks):**

1. **Three.js CAD Inspection Viewer** — High-detail procedural 3D assembly of the **Polymaker Black PETG Rover** and the **HQST 100W 9BB Solar Garage Docking Bay** with custom procedural canvas textures (FDM layer-line PETG, 9BB monocrystalline solar cells, GOLDENMATE LiFePO4 wrap, Arduino Uno R3 teal PCB, Raspberry Pi 5 PCB). Supports wireframe toggle, **Exploded View** (elevates the stealth-black PETG upper armored carapace to expose the internal GOLDENMATE 12V 10Ah LiFePO4 battery, SANOOV Pi 5 + Active Cooler, Arduino Uno R3, YRDZXG 5A Buck Converter, and 6× spinning 3007 fans), camera presets, and subsystem inspection focus buttons.
2. **Lunar route simulator** — SVG path (`#svg-path`); rover marker follows path length; speed/ETA/slope change near scripted crater/boulder zones along an **850 m** nominal traverse.
3. **Payload calculator** — Checkboxes with `data-mass` / `data-power`; computes Earth mass, **lunar weight** using \(g_{\text{lunar}} = 1.622\,\text{m/s}^2\), capacity vs **500 kg**, simplified CoG offset text, and energy estimate.

**Run locally:** open `index.html` in a browser, or any static server from repo root.

### 5.2 Autonomous navigation LLM template (`payload.json`)

**Purpose:** Frozen **few-shot system prompt** for macro **left / right / none dodge** from 10 clearance channels and hazard tags.

**Contract:**

- Input: sensor string `FL, FC, FR, cL, cR, SL, SR, BL, BC, BR` (meters), waypoint, hazard list.
- Output: **only** JSON: `{"dodge":"none"|"left"|"right"}`.
- Safety: never dodge **into** pits, craters, or steep mountains.

**Usage:** Load into Ollama (or compatible runtime) as the modelfile / system template for model id `hunch-rover-nav` based on `qwen2.5-coder:7b`. Wire this to onboard middleware on the physical rover when that stack exists; today it documents the intended AI behavior for reviews and sim integration.

### 5.3 LLASO Digital Twin & 3D Autopilot Simulator (`Hunch/nasa-llaso-cad/`)

**Purpose:** **Project 1 & 2** — 40-ft × 3 m cylindrical cargo module, LIFO 14-day logistics, and the **60 FPS WebGL Lunar Rover & Solar Garage Docking Simulator (`viewer.html`)**.

**CAD / assets:**

| Asset | Role |
| :--- | :--- |
| `generate_llaso_cad.py` | Parametric STL/OBJ/URDF generation |
| `meshes/*.stl` | Hull, racks, CTBs, cryo tanks, gantry, etc. |

| `Lunar_Constraints_and_Sim_Flaws.pdf` | Known sim vs reality gaps |

**Logistics:**

| Asset | Role |
| :--- | :--- |
| `optimize_manifest.py` | Builds manifest, assigns bays/tiers, computes **CoM** \(\mathbf{r}_{\text{CoM}}\), Earth vs lunar weight |
| `lunar_logistics_manifest.json` | Source of truth for viewer timeline + NASA 5 variables per item |

**Five NASA tracking variables (every manifest line):** Item, Quantity, Location \([X,Y,Z]\) + bay metadata, Time Needed (mission day 1–14), Responsible Actor.

**LIFO rule:** Day-1 items load **last** on Earth (near forward hatch); Day-14 items load **first** (deep aft). Optimizer enforces lateral CoM within roughly **±0.05 m** in Y.

**Simulator (`viewer.html` — PETG BOM v6 Edition):**

- **Polymaker Black PETG Rover 3D Assembly (`roverGroup`):**
  - **Exterior:** Enclosed stealth-black 3D-printed PETG armored shell (`createPetgTex` / `createPetgBumpTex` with 0.2mm FDM layer lines & lunar regolith dust weathering), 24× M3/M4 brass heat-set inserts, 6× flush **30×30×7mm (3007) brushless cooling fans** (3 left intake, 3 right exhaust with spinning 7-blade impellers), waterproof SP13/GX16 aviation bulkhead connectors, rear 5-segment BMS state-of-charge LED bar, E-Stop button, and top magnetic charging contact pad.
  - **Exploded Shell Cutaway (`E` key or `🔧 EXPLODE (E)` button):** Smoothly lifts `upperShellGroup` by `+0.28m` to reveal the internal avionics bay: **GOLDENMATE 12V 10Ah LiFePO4 battery** (`128Wh`), **SANOOV Raspberry Pi 5 4GB + Active Cooler** (with spinning radial blower fan), **Arduino Uno REV3 [A000066]** teal PCB, **YRDZXG 12V/24V-to-5V 5A Buck Converter**, and braided silicone wiring harnesses.
  - **6-Wheel Rocker-Bogie Drivetrain:** Articulated black PETG rocker-bogie legs with brass differential pivot bushings, **6× Greartisan DC 12V 100RPM 37mm centric spur gear motors** (silver 37mm gearboxes + black motor cans + red/black motor leads), brass hex couplers, and deep-chevron TPU/PETG tires with non-penetration terrain solver.
  - **Sensors:** Spinning **EC Buying YDLIDAR X2L 360°** turret (8m range) + **2× Arducam 5MP 1080P OV5647 camera modules** (1 forward navigation Mastcam + 1 rear auto-docking alignment camera).
- **Industrial Lunar Hangar Bay // HQST 100W Solar Docking Station (`dockGroup` at `[-15, -15]`):**
  - **Roof Solar Array:** Angled **HQST 100W 12V 9BB Monocrystalline Solar Panel** (`createSolarTex`, 1024×1024 6×6 cell matrix with 9 busbars per cell, octagonal wafers, anodized aluminum frame, IP65 junction box, and adjustable tilt-strut rack).
  - **Wall-Mounted MPPT Solar Controller Cabinet:** Heatsink enclosure with MC4 red/black PV cables and live OLED display (`18.4V 5.4A • 100.0W • 13.8V LiFePO4 CC/CV`).
  - **Hangar Bay Mechanics:** Corrugated titanium-slate walls with rivets and `LLASO SOLAR DOCK // BAY 01` stencils, 4 steel I-beam portal frame ribs, diamond-plate deck with sloped hazard entry ramp, wheel-guide chock rails, **5 sequential pulsing LED floor alignment chevrons** (turning solid emerald when docked), 6-slat segmented overhead door with vision window, and an **articulated overhead magnetic 4-pogo-pin charging arm** (`+100W` solar charging into the `128Wh` GOLDENMATE LiFePO4 battery).
- **Camera Views & Controls:**
  - `1 CHASE`, `2 MASTCAM`, `3 SATELLITE`, `4 CAD ORBIT` (close orbit around rover), `5 DOCK BAY` (close orbit around the HQST 100W Solar Garage Docking Station with hangar door open).
  - `WASD` manual drive, `E` toggle exploded shell cutaway, `H` headlights, `M` synthesized audio, `RTH` autonomous return-to-dock.
- **Autonomy Stack:** LiDAR → log-odds occupancy grid → A\* → Pure Pursuit; 60 FPS ONNX Neural Imitation Pilot (`rover_pilot.onnx`); optional Ollama VLM strategic planner; automatic reverse-escape supervisor.

## 6. Autonomy layers (conceptual stack)

On the **LLASO WebGL rover sim**, multiple layers can run together or be toggled:

| Layer | Mechanism | Output |
| :--- | :--- | :--- |
| Reactive | Proximity / dodge bias, reverse supervisor | Immediate steer/throttle overrides |
| Geometric | Occupancy map + A* + Pure Pursuit | Collision-free path to goal |
| Strategic | Ollama + prompt (related to `payload.json` dodge policy) | High-level decisions / logging |
| Imitation | `rover_pilot.onnx` | Continuous steer/throttle from camera + telemetry |

On **AEGIS-V1 root site**, autonomy is **presentational** (route SVG animation + calculator), not closed-loop physics.

On **React rover dashboard**, autonomy modes are **UI state** (`AUTONOMOUS_CRAWL`, etc.) driving simulated telemetry until hardware integration lands.
